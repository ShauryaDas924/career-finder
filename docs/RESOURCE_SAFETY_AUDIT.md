# Resource Safety and Trust Audit

**Research date:** September 30, 2026  
**Dataset reviewed:** all 64 resources present at the start of this audit  
**Scope:** destination ownership, maintenance, student relevance, moderation/reporting signals, privacy and security disclosures, URL integrity, duplication, and repository-specific risk

## Important limitation

This audit evaluates the resource destination and its operator. It does **not** verify every job, internship, fellowship, recruiter, employer, outbound link, or future listing available through that destination. `KEEP` means the destination was identifiable, current, useful, and sufficiently trustworthy to retain; it is not a promise that every opportunity on it is safe or genuine.

Students should independently confirm an opportunity through the employer's official domain before sharing sensitive information. No repository, package, dependency, script, binary, container, or take-home assessment was downloaded or executed during this audit.

## Methodology

1. Read every original record in `app/data/resources.ts`, including its stored URL, description, categories, search terms, audience guidance, update claim, and note.
2. Checked the expected destination and hostname, identifiable operator, current content or maintenance signals, student or early-career usefulness, and unnecessary or unexplained redirects.
3. Preferred first-party operator, government, professional-association, privacy, terms, help, moderation, reporting, and repository-history evidence. When a board blocked automated access, ownership and currentness were corroborated through first-party association pages and current support, pricing, or program material.
4. For GitHub resources, inspected the public README, history, ownership, issue/reporting paths, outbound-link pattern, and whether the useful content could be read without executing code. GitHub hosting alone was not treated as employer or link verification.
5. Compared overlapping resources for freshness, governance, transparency, and unique coverage.
6. Assigned exactly one decision to every original resource.

## Security and scam research

The public guidance added to Whoopberry is intentionally calm: verify an unexpected technical assessment through the company's official domain before running unfamiliar code. This is supported by current, authoritative evidence:

The confirmed patterns include fake recruiters and lookalike employer domains; fake checks and equipment-purchase requests; premature banking or identity-document collection; Telegram, WhatsApp, text-only, or other off-platform recruiting; fake remote-work, task, and cryptocurrency offers; and technical assessments that use unfamiliar repositories, dependency installation, workspace settings, shell scripts, containers, or binaries as an execution path.

- The [FTC job-scam guide](https://consumer.ftc.gov/articles/job-scams?os=a) and [2025 recruiter-scam warning](https://consumer.ftc.gov/consumer-alerts/2025/07/job-scammers-are-looking-hire-you) recommend independently contacting the organization and warn against payment, fake checks, and premature personal-information requests.
- The FBI warns that fake jobs can be used to collect identity information or route victims through lookalike websites in its [fake job-listing advisory](https://www.ic3.gov/PSA/2020/PSA200121), and that “task” scams may demand cryptocurrency payments in its [work-from-home advisory](https://www.ic3.gov/PSA/2024/PSA240604).
- Microsoft's [Contagious Interview analysis](https://www.microsoft.com/en-us/security/blog/2026/03/11/contagious-interview-malware-delivered-through-fake-developer-job-interviews/) and Palo Alto Networks Unit 42's [campaign analysis](https://unit42.paloaltonetworks.com/two-campaigns-by-north-korea-bad-actors-target-job-hunters/) document fake developer interviews that deliver malicious code or dependencies. Unit 42 also describes recruiter-channel and identity risks in its [communication-channel research](https://unit42.paloaltonetworks.com/communication-channel-identity-risks/).
- Visual Studio Code's [Workspace Trust documentation](https://code.visualstudio.com/docs/editing/workspaces/workspace-trust) explains that an unfamiliar workspace can influence tasks, debugging, extensions, and settings. npm's [install documentation](https://docs.npmjs.com/cli/install/) documents lifecycle-script behavior and the `ignore-scripts` control.
- GitHub provides [abuse and spam reporting](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam), but repository hosting does not verify a recruiter, employer, dependency, outbound link, or assessment. Docker likewise warns against building untrusted sources in its [security guidance](https://docs.docker.com/security/security-announcements/).

These patterns do not mean that a normal coding assessment is malicious. The practical distinction is whether the request is expected, attributable to a verified employer/recruiter, and confirmed through the company's official channel before any unfamiliar repository, package, script, container, or binary is executed.

## URL, repository, and destination findings

- No typo-squatted or unexplained malicious destination was found among the original 64 records.
- BioSpace's stored URL used an unnecessary same-operator redirect. The canonical direct board root is `https://jobs.biospace.com/`.
- InternList's application links route to Simplify, which exposed duplication and weaker operator/policy transparency rather than malware. It is replaced by the existing Simplify record.
- No inspected GitHub directory was proven malicious. All were useful as readable tables without cloning or execution.
- The Vansh directory was removed because its meaningful maintenance stopped while the recruiting cycle continued and a stronger, current, overlapping Simplify/Pitt directory already existed. It was not labeled malicious.
- The six remaining GitHub destinations stay in the catalog with accurate community/intermediary caveats. Their public repository history is a useful transparency signal, not verification of every linked employer.
- Several association boards returned anti-bot responses to automated research requests. First-party association pages and current board/support/program evidence confirmed their ownership and operation; an automated access denial was not treated as a broken destination.
- No resource remained unassessable after the ownership and first-party corroboration review.

10. Add one site-level limitation explaining that Whoopberry curates useful destinations but students must independently verify individual opportunities, plus one technical-assessment safety tip.

After the two record removals/replacement, the maintained dataset contains 62 resources. No subject area loses meaningful coverage: the Simplify/Pitt directory covers the removed stale tech list, and the existing Simplify platform covers InternList's underlying source. Narrowing Dreamwork and SelectLeaders metadata improves search accuracy without removing their supported specialty coverage.

## Future recheck protocol

Recheck resource destinations on a regular editorial cadence and sooner when users report a problem. For each recheck:

1. Confirm the stored HTTPS URL, final hostname, operator identity, and any redirect.
2. Confirm recent content or maintenance, especially for recruiting-cycle GitHub lists.
3. Re-read privacy, terms, reporting, moderation, and scam-warning material when it changes.
4. Verify that descriptions, categories, search aliases, update claims, and class-year guidance still match the destination.
5. Prefer original employer, government, university, or association pages over opaque republishers when coverage is equivalent.
6. For GitHub resources, inspect history and issues statically; do not clone, install dependencies, run scripts, open untrusted workspaces with full trust, build containers, or execute binaries to perform an editorial review.
7. Record evidence and a new research date. Never convert a publisher's own “verified” language into a Whoopberry guarantee.

## Bottom line

The audit found two resources that should not remain in the maintained dataset: the stale/redundant Vansh directory and the opaque InternList layer, which is replaced by the already-present Simplify source. Twenty-three otherwise useful resources have documented cautions. No GitHub directory was proven malicious, no unexpected hostile URL was found, and no resource remained unassessable. Whoopberry audits useful destinations; it cannot guarantee every external listing, recruiter, employer, or technical assessment.
